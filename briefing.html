02Phase별 진척

계획서 15장 단계별 개발 일정 기준. Phase 9(배포·테스트)가 현재 지점입니다.

PHASE 1 기존 코드 정리 완료
화면과 API 코드 분리, 공통 타입 정의, 환경변수 일원화, 오류 처리 통일
PHASE 2 로그인과 DB 완료
구글 로그인 구현(서버에서 구글 공개키로 토큰 검증), users·프로필·동행인 테이블, 기존 localStorage 데이터 계정 이전.
  • DB를 Turso 클라우드로 이전 완료 — 배포 시 데이터 유실 방지
PHASE 3 지도와 식당 완료
Google Places API 연동, 주변 음식점 검색, Place ID 기준 식별, 식당 상세 화면.
  • 지도 한도 초과 시 데모 데이터로 자동 전환 — 장애 시에도 화면이 깨지지 않음
PHASE 4 식당별 메뉴 완료
메뉴 테이블·조회, 미등록 메뉴 촬영 등록, 분석 결과 저장, 중복 처리.
  • 사용자가 늘수록 가게별 메뉴·알레르기 정보가 축적되는 구조
PHASE 5 공개 데이터 부분 완료
식약처 식품영양성분 DB · USDA FoodData Central 연동, 정규화 및 캐시 구축 완료.
  • 식약처 푸드QR — 활용신청 승인 대기
  • 식약처 제품 LOT 원자재 — 활용신청 승인 대기
PHASE 6 AI 정확도 향상 완료
공개 데이터를 AI 분석 근거로 주입하는 RAG 구조, 구조화 JSON 출력, 칼로리 범위 계산, 알레르기 교차 검증, 재료 기반 할랄·베지테리언 판정.
  • DB 우선 조회 — 이미 분석된 음식은 AI를 다시 호출하지 않음(비용 절감)
PHASE 7 추천 완료
안전 필터, 추천 점수(안전 40% · 식단 20% · 거리 15% · 다양성 10% · 신뢰도 10% · 평점 5%), 추천 이유 표시, 지도 추천 패널
PHASE 8 사용자 제보 부분 완료
오류 신고 접수, 검증 상태, 신뢰도 재계산, 제보 누적 반영(있음 1건 / 없음 2건 이상).
  • 증거 이미지 업로드 — 서버는 준비 완료, 화면만 미구현
PHASE 9 테스트 및 웹 배포 현재 지점
배포 방식 결정 대기 중. 상세는 05~07번 항목 참조
PHASE 10 모바일 앱 전환 미착수

03이번 회차 수정

지적하신 사용성 문제 5건과, 원인 규명이 필요했던 다국어 문제를 처리했습니다.

문제조치
할랄 미선택자에게 할랄 경고 표시저장된 경고 재사용을 제거하고, 조회 시점 사용자 조건으로만 재계산
하단 내비게이션이 화면 밖으로 밀림고정 높이(844px)를 실제 화면 높이 기준으로 변경
"구글 지도에서 보기" 링크 중복메뉴 없음 안내 쪽 링크 삭제
게스트 모드에 저장 버튼 없음실제로는 자동 저장되고 있었음 — 자동 저장 안내와 로그인 유도 추가
도보 시간이 실제보다 짧게 표시우회 보정 1.3배 적용, 문구를 "약 N분 (직선거리 기준 추정)"으로 변경. 추가 비용 없음

식당 이름 다국어 혼재 — 원인 규명

구글에 한국어를 요청해도 같은 문자열을 돌려주는 것을 확인했습니다. 가게 주인이 검색 노출을 위해 이름 자체를 여러 언어로 등록해 둔 경우로, API 설정으로는 해결되지 않습니다. 표시 언어로 읽을 수 없는 문자가 섞여 있을 때만 잘라내는 방식으로 처리했습니다. 

Mongvely … | 焼き肉 焼肉 | 烤肉 l 무한리필 몽블리 명동점  →  무한리필 몽블리 명동점
โตซาลาเปา Chinese Steamed Buns 包子                    →  Chinese Steamed Buns
FLIPPER'S 시부야                                       →  그대로 유지  (브랜드명 보존)

기존 저장분 184건 중 12건을 정리했습니다.

04보안 · 비용 방어

배포 시 API 키 유출로 요금이 청구될 위험을 발견하여 조치했습니다. 모든 항목은 실제 동작으로 검증했습니다.

발견된 위험조치검증 결과
유료 검색용 지도 키가 방문자 전원에게 노출브라우저용 / 서버용 키 분리서버 키 노출 없음
식당 사진 주소에 API 키 포함서버 경유 방식으로 변경키 미포함
이미지 검색 키가 빌드 파일에 포함서버 경유 방식으로 변경빌드 내 키 0건
메뉴 분석 API에 호출 제한 없음 (AI 요금)분당 20회 제한25회 중 5회 차단
관리자 API에 인증 없음 (공공데이터 대량 호출)토큰 인증 추가운영 모드 차단
현재 요금 위험은 없습니다. 구글 클라우드 프로젝트에 결제 수단이 등록되어 있지 않아, 현시점에서는 요금이 청구될 수 없는 상태입니다. 다만 카드를 등록하는 순간 이 안전망이 사라지므로, 등록 직전에 반드시 할당량 상한을 먼저 걸어야 합니다.

05회의 결정사항

아래 세 가지가 정해져야 다음 작업으로 넘어갈 수 있습니다.

결정 01배포 방식
선택지비용카드 등록작업량
Cloud Run무료 한도 내 0원필요보통
Vercel무료불필요서버 코드 일부 개조

이미 지도·로그인을 Google Cloud에서 사용 중이라 계정 일원화 측면은 Cloud Run이 유리합니다. 카드 등록을 피하려면 Vercel입니다.

결정 02최종 형태
선택지내용추가 작업
PWA (홈 화면 설치형 웹)배포하면 사실상 완성. 스토어 심사 없음거의 없음
네이티브 앱 (Phase 10)React Native / Flutter로 화면 재구현큼

현재 UI가 이미 모바일 크기 기준으로 제작되어 PWA 전환 비용이 낮습니다. 어느 쪽을 택하든 서버 배포는 반드시 선행됩니다 — 앱도 이 서버를 사용하기 때문입니다.

결정 03도메인

Cloud Run 기본 주소(무료)를 쓸지, 별도 도메인을 구매할지 결정이 필요합니다. 한 번 정한 뒤 변경하면 구글 로그인을 다시 설정해야 하므로 고정을 권장합니다.

현재 구글 로그인이 되지 않는 원인이기도 합니다. 임시 테스트 주소가 재시작마다 바뀌어 승인 주소로 등록할 수 없는 상태입니다.

07현장 테스트

계획서 17장 기준. 실제 식당에서 직접 검증이 필요합니다. 준비물은 스마트폰과 서로 다른 알레르기·식단 조건을 설정한 계정 2개 이상입니다.

실사용 시나리오

  1. 식당 앞에서 지도 검색실제 위치의 식당이 뜨는가, 거리 표시가 맞는가
  2. 해당 식당 선택이름·평점·주소가 정확한가, 이름이 설정 언어로 나오는가
  3. 메뉴판 촬영 후 분석메뉴명을 제대로 읽는가, 몇 초 걸리는가
  4. 분석 결과 확인재료·알레르기·칼로리가 실제와 맞는가
  5. 식당에 메뉴 등록등록 후 다시 들어갔을 때 저장돼 있는가
  6. 다른 기기로 같은 식당 조회등록한 메뉴가 남에게도 보이는가 — 서비스의 핵심 전제
  7. 다른 조건 계정으로 조회그 사람 조건에 맞는 경고가 나오는가 — 이번에 고친 문제의 검증
  8. 실제 성분 확인 후 오류 신고신고가 접수되고 신뢰도에 반영되는가
  9. 같은 메뉴 재촬영AI를 다시 부르지 않고 저장된 결과를 쓰는가 — 비용 절감 검증
  10. 추천 목록 확인추천 이유가 납득 가능한가

데이터 테스트 계획서 17.2

  • 메뉴명 오타 / 손글씨 메뉴판 / 흐린 사진
  • 현지어만 있는 다국어 메뉴판
  • 같은 음식의 다른 표기 (비빔밥 / 비빔 밥 / Bibimbap)
  • 공개 데이터에 없는 현지 음식

안전 테스트 최우선

  • 설정한 알레르기와 표시되는 경고가 정확히 일치하는가
  • 데이터가 없을 때 단정적으로 "안전하다"고 말하지 않는가
  • 심각한 알레르기 조건에서 확인 문구가 나오는가
  • 공식 데이터와 AI 추정이 충돌할 때 어느 쪽을 따르는가
안전 테스트에 가장 많은 시간을 배정할 것을 권장합니다. 알레르기 정보의 정확도는 서비스 신뢰와 직결됩니다. 실패한 케이스는 메뉴판 사진과 화면 캡처, 분석 소요 시간을 함께 기록해 주세요.
